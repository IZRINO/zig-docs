# Zig 0.17.0 双语文档

以 Astro 7.4.1 和 Starlight 0.42.6 构建的 Zig 0.17.0 固定版本文档站。收录官方语言参考和官方标准库文档资产覆盖的全部模块，提供简体中文与英文阅读、接口索引、全文搜索、源码行定位和语言切换。

- 网站：<https://izrino.github.io/zig-docs/>
- 官方原文：<https://ziglang.org/documentation/0.17.0/>
- 默认语言：简体中文。中文路由 `/zh-cn/`，英文路由 `/en/`。

## 本地开发

需要 Node.js 24。日常构建直接读取仓库中的快照与译文，不联网抓取，也不调用翻译服务。

```sh
npm ci
npm run dev
```

访问 `http://localhost:4321/zig-docs/`。开发服务器不提供正式全文索引；搜索需要构建后通过预览服务器验证。

```sh
npm test
npm run lint
npm run check
npm run build
npm run validate:links
npx playwright install chromium
npm run test:e2e
```

`build` 先执行完整内容校验，再构建静态站点与 Pagefind 索引。译文缺失、代码标记变更、快照校验和不匹配或页面集合不完整都会阻断构建。

## 内容与来源

- `upstream/0.17.0/`：官方语言参考、标准库页面、JavaScript、WebAssembly、源码归档和许可证。
- `upstream/0.17.0/manifest.json`：版本、来源、抓取时间、资源大小与 SHA-256。
- `translations/`：逐段译文及原文哈希；标准库按注释内容去重，保留全部源码位置。
- `content/{en,zh-cn}/`：生成后的结构化页面与导航清单。
- `reports/`：覆盖率、声明与源码位置清单、上游无法解析的引用记录。
- `scripts/`：快照、官方解析器适配、翻译校验和内容生成。
- `tools/tokenizer.wasm`：使用 Zig 0.17.0 官方词法分析器编译的独立校验模块。

语言参考按 53 个顶层章节组织，保留 352 个标题。标准库按官方归档的 538 个源码模块组织，保留 37,803 个声明记录，包括私有声明、条件类型成员、类型函数及别名。官方解析器会为不同局部容器生成相同完整名称；同一页面中遇到这种情况时，后续声明以源码行号补充锚点，避免覆盖记录。

中文翻译保留标识符、字面量、命令及编译器输出，仅翻译自然语言与代码注释。代码通过官方词法分析器比较非注释标记；注释行数不足时补空注释，以保持原始行号。原文的语义和限制条件优先于措辞润色；上游没有提供说明的接口不补造说明。

`verbatim-*.json` 记录经审阅后原样保留的代码、公式、路径和技术专名。包含拉丁字母而不含汉字的单元必须登记明确理由，单词说明也受此门禁约束。`protected-exceptions-*.json` 仅允许指定原文与译文哈希之间的精确修正，用于处理上游未闭合反引号、ASCII 图示中的自然语言标签等情况。带 `renderedTextBlocks` 标记的图示还必须与同一源码模块的原文、译文围栏逐字匹配；它们不会关闭实际源码的词法标记校验。

所有站外回退引用都会通过官方解析器再次查找；官方能够解析、但站内没有收录的目标会阻断生成。真正无法解析的上游引用保存在 `reports/upstream-links.json`。`reports/semantic-review.json` 记录额外的敏感语义抽样、英文残留扫描及修正依据；抽样结果不等同于对全部译文的正确性证明。

大型标准库模块使用可筛选、分页和键盘操作的接口索引，全部正文与接口锚点仍保留在当前页面。`reports/verification.json` 保存首次发布前的本地验收统计与性能测量；本地性能数据不代表线上网络延迟。`reports/deployment.json` 记录首次部署的提交、通过全部门禁的工作流和实际线上验收结果。

## 手工更新与审核

此仓库只维护 0.17.0，不跟随开发版本自动更新。维护者手工执行：

```sh
npm run snapshot
npm run extract
```

快照脚本复用已有固定资源；若需重新抓取，应先将旧快照移到工作区外备份，再运行脚本。脚本还会下载并校验官方源码压缩包以提取许可证，临时压缩包保存在 `.cache/`。Linux/macOS 需要支持 xz 的 `tar`；Windows 的 `tar` 不支持 xz 时使用 Python 3 标准库回退。

原文发生变化时，需要审核来源及校验和、重新建立翻译清单、补齐译文，再生成内容。必须审查内存所有权、分配释放、并发、未定义行为、错误传播和数值边界等语义，并运行全部校验。禁止用英文原文代替缺失中文通过构建。

对于评审过程中发现的疑似上游笔误，参见 `reports/upstream-notes.json`。页面翻译忠实保留了固定版本原文，这些记录不是对上游行为的更正。

修改词法分析器包装时，需要同版本 Zig 编译器，具体编译命令见 `scripts/tokenizer.zig`。重新编译后同时更新校验和并运行词法分析测试；一般构建无需安装 Zig。

## 部署

GitHub Pages 使用 Actions 部署。推送 `main` 或手工触发工作流后，先测试、检查格式和类型、校验内容、构建、检查站内链接与浏览器交互，再上传并部署静态产物。校验失败不会替换已部署站点。

站点固定部署于仓库子路径 `/zig-docs/`。修改仓库名称或部署域名时，需要同时更新 Astro 配置、生成器中的站内链接、测试与工作流。
