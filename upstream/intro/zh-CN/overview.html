核心特性一览

小巧而精炼的语言

专注于调试你的应用程序，而不是把时间浪费在调试你的编程语言知识上。

Zig 的完整语法仅由一份 580 行的 PEG 语法文件即可精确定义。

没有隐式控制流，没有隐式内存分配，没有预处理器，也没有宏。如果一段 Zig 代码看起来没有跳转去调用函数，那它就绝对没有。这意味着你可以完全确定：下面的代码只会先调用 foo()，紧接着调用 bar()，并且无需预先了解任何变量的具体类型就能做出这一绝对保证：

var a = b + c.d;
foo();
bar();

隐式控制流的典型反例：

  • D 语言拥有 @property 函数，使得看似普通的字段访问实际上在隐式调用方法。
  • C++、D 和 Rust 拥有运算符重载，因此 + 运算符可能会悄悄调用函数。
  • C++、D 和 Go 拥有抛出/捕获异常机制，因此 foo() 可能会抛出异常并阻止 bar() 的调用。

Zig 将所有的控制流完全约束在显式关键字和显式函数调用之中，以此极大提升代码的可维护性与可读性。

谈到性能，Zig 的执行效率甚至优于 C。

  • 所有 Zig 代码都处于同一个编译单元中，能够进行全局联合优化。
  • 精心定义的非法行为。例如，在 Zig 中，有符号和无符号整数溢出均属于未定义行为；而在 C 语言中仅有有符号整数溢出属于未定义行为。这有助于实施 C 语言中无法实现的更激进优化。
  • Zig 直接在语言层面提供 SIMD 向量类型，使得编写可移植的向量化代码变得极其简便。
  • 标准库开箱即用提供了哈希表（HashMap）和动态数组（ArrayList）等核心现代数据结构；而在 C 语言中由于缺乏标准实现，开发者往往因图省事而被逼使用低效的链表。
  • 默认开启当前 CPU 架构的高级指令集特性（除非进行交叉编译）。

手动内存管理

用 Zig 编写的软件库，几乎可以被部署到任何场景中运行：

  • 桌面端应用程序
  • 低延迟服务器
  • 数据库系统
  • 操作系统内核
  • 嵌入式硬件设备
  • 实时软件系统（例如现场演出控制、飞行器控制、心脏起搏器等）
  • 通过 WebAssembly 在 Web 浏览器或插件沙箱中运行
  • 遵循 C ABI 供其他编程语言调用

为了达成这一严苛的目标，Zig 开发者必须完全自主掌控内存生命周期，并显式处理每一次内存分配可能出现的失败。

Zig 标准库亦严格遵循这一原则。任何需要分配内存的函数都必须显式接收一个分配器参数。正因如此，Zig 标准库甚至能直接运行在无宿主操作系统的裸机环境（freestanding）中。

除了一套全新视角的错误处理机制外，Zig 还提供了 defer 和 errdefer，使得所有资源的管理（不仅限于内存，还包括文件句柄、互斥锁、网络连接等）变得轻而易举且直观可靠。

无需 FFI 与绑定即可直接集成 C 库

@cImport 能够直接导入 C 语言的类型、变量、函数以及简单宏供 Zig 代码使用，它甚至能自动将 C 语言的内联函数翻译为等价的 Zig 函数。

这段 Zig 代码比对应的 C 语言代码更加简洁明了，同时拥有更高的安全性保护，而这一切只需直接导入 C 头文件即可完成——无需编写任何额外的 API 绑定。

Zig 在使用 C 语言库方面，甚至比 C 语言自身还要得心应手。

Zig 本身就是一个顶级的 C 语言编译器

下面是使用 Zig 编译 C 代码的简单示例：

hello.c 
#include <stdio.h>

int main(int argc, char **argv) {
    printf("Hello world\n");
    return 0;
}

$ zig build-exe hello.c -lc
$ ./hello
Hello world

你可以使用 --verbose-cc 参数，查看 Zig 在底层实际调用的 C 编译器完整指令：

$ zig build-exe hello.c -lc --verbose-cc

请注意：如果再次运行该命令，终端将没有任何多余输出，且能瞬间完成构建：

$ time zig build-exe hello.c -lc --verbose-cc

这得益于构建产物缓存系统。Zig 能够自动解析 .d 依赖描述文件，凭借强健细致的缓存机制彻底杜绝一切无意义的重复编译。

Zig 不仅能编译 C 代码，而且还有一个极其重磅的理由促使你把 Zig 当作主力 C 编译器：Zig 自带 libc。

导出函数、变量与类型供 C 代码调用

Zig 最主要的应用场景之一，就是导出遵循 C 语言 ABI 的库供其他语言或 C 代码链接使用：

要构建静态链接库：

$ zig build-lib mathtest.zig

交叉编译是一等公民

Zig 在构建所有受支持的目标平台时完全独立于当前宿主系统。没有所谓的“交叉编译工具链”概念；每个 Zig 编译器安装包都可以直接面向所有目标平台进行构建：

现在我们分别为 x86_64-windows、x86_64-macos 和 aarch64-linux 目标平台进行构建：

$ zig build-exe hello.zig -target x86_64-windows
$ file hello.exe
hello.exe: PE32+ executable (console) x86-64, for MS Windows
$ zig build-exe hello.zig -target x86_64-macos
$ file hello
hello: Mach-O 64-bit x86_64 executable, flags:<NOUNDEFS|DYLDLINK|TWOLEVEL|PIE>
$ zig build-exe hello.zig -target aarch64-linux
$ file hello
hello: ELF 64-bit LSB executable, ARM aarch64, version 1 (SYSV), statically linked, with debug_info, not stripped

这支持在任何 Tier 3+ 目标平台上，为任何 Tier 3+ 目标平台进行交叉编译。

对软件包维护者极其友好

虽然 Zig 已经实现自举，但从源码构建时只依赖系统已有的标准 C/C++ 编译器和 LLVM/Clang。

对于希望彻底杜绝任何二进制预编译产物（Binary Blobs）的 Linux 发行版，我们设计了完整的自举引导链路，可以从零由 C 源码阶段性引导至最新自举编译器。

未来，我们希望启发并协助第三方社区实现独立的 Zig 解释器或纯 C 后端编译器。

构建系统将操作系统与发行版集成作为明确的第一类需求来支持。

所有非 Debug 构建模式均支持确定性复现编译（Reproducible / Deterministic Builds）。
