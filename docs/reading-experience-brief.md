# 文档阅读界面优化简报

状态：已实施；用户确认使用开源中文字体。验证数据见 `reports/reading-experience.json`。

界面模式：Read。以连续阅读、查阅示例和定位接口为主要任务，沿用现有橙色强调、双语路由和三栏导航。

## 阅读任务

面向阅读中文语言参考、查阅英文术语和标准库接口的 Zig 开发者。
保留现有橙色强调与明暗主题，以正文、示例、接口签名为视觉中心。

## 当前依据

检查页面：`/zig-docs/zh-cn/reference/Slices/`，浏览器宽度 1004px。

- 正文计算字号 15.2px，代码 12.96px，正文宽度 668px。
- 当前字体依赖系统安装；正文以 Segoe UI 开始，代码以 Cascadia Code 开始。
- 文件名单独采用斜体，运行输出与示例共用代码容器视觉样式。
- Starlight 已安装 Expressive Code 0.44.2，但结构化 HTML 注入绕过代码围栏处理。

## 实施方向

1. **字体与字号**：自托管 Source Sans 3 与 Noto Sans SC，分别承担拉丁文本与中文；代码使用 JetBrains Mono，中文注释回退至同一中文字体。保留字体许可证，按字符范围分片加载，使用 `font-display: swap`。正文桌面 17px、移动端 16px；代码约 14px。中文取消负字距，代码关闭连字。
2. **标题与层级**：主标题桌面 40px、移动端 32px，字重 750；二级标题 28px，三级标题约 21px。使用固定角色字号与正常字距。标题前留白大于标题后留白。面包屑、版本信息与正文明确分层，移除重复分隔线并缩短正文前的空白。
3. **布局**：宽屏保留章节、正文、页内目录三栏；中等宽度优先正文，目录先折叠、章节栏再进入抽屉。英文正文约 65–75 个字符一行，中文正文约 40–45 个汉字一行；代码和表格可比正文略宽。重点验证 390px、768px、1004px、1440px。
4. **代码框**：语言参考的完整示例接入 Expressive Code，文件名进入统一标题栏，复制操作固定在工具区；命令输出使用明确的“命令行 / Terminal”标题与独立表面色。长行支持键盘聚焦及横向滚动；保留代码原始换行，不新增换行开关。标准库的短签名与源码保留上游高亮、原始行号、行锚点与折叠入口。
5. **视觉力度**：通过标题尺度、正文对比、选中导航和代码容器边界增强识别；橙色集中用于链接、焦点和当前章节。避免给长文阅读增加装饰性模块。

## 代码展示库比较

| 方案            | 核对结果                                                                                           | 本站取舍                             |
| --------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Expressive Code | 已安装；可通过构建时渲染 API 接收代码字符串，提供文件标题、复制及主题；真实 Zig 示例已完成渲染探测 | 首选用于完整示例与输出               |
| Shiki           | 本地 API 提供 `codeToHtml`、`codeToTokens` 等高亮接口；Expressive Code 自身使用 Shiki 插件         | 单独接入仍需实现外框与交互，收益有限 |
| Prism           | 本地版本 1.30.0，提供语法高亮与插件体系                                                            | 当前无需引入另一套高亮管道           |

真实示例探测：原代码 1324 字符；现有代码块 HTML 4067 字节，Expressive Code 默认双主题渲染结果 19989 字节，约 4.91 倍。此数值仅比较该代码块的未压缩 HTML，不代表页面总载荷或浏览器脚本大小。

因此不对全部接口签名、大型源码清单统一套用较重渲染。短签名与源码继续使用上游高亮，只统一字体、间距、对比和工具区样式。

参考： [Expressive Code](https://expressive-code.com/)、[Shiki](https://shiki.style/guide/)、[Prism](https://prismjs.com/)。

## 实施约束与验收

- 页面内容、双语路由、原始锚点、搜索、源码行映射保持有效。
- 代码字符串与输出不得因展示而改变；保留制表符，核对复制内容与原文一致。
- 字体从项目静态资源加载，日常构建不依赖第三方字体服务。
- 检查中文注释、英文长标识符、表格、嵌套类型和大型平台模块。
- 验证明暗主题、移动导航、键盘焦点、复制、原始换行、深层链接和语言切换。
- 执行内容校验、现有单测、格式检查、类型检查、构建、内部链接检查、浏览器测试及性能检查。
- 检查新增字体的实际下载量与大型页面性能，再提交和部署。
